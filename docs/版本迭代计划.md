# 学习台版本迭代计划

编写日期：2026-09-30

代码基线：`0.1.25`，`main` 提交 `79c1748`

应用版本号现为 `0.1.29`，这一档只把已有 EAS 项目 id 写入 `app.json`。`0.1.28` 增加了 EAS / TestFlight 配置。产品功能仍是 `0.1.27` 的前两版实现；自动化与构建结果见[验收记录](验收/0.1.26-0.1.27-验收记录.md)。iPad 真机和家庭试用尚未完成。下表里的「0.1.28 逐词复习」规格仍待实现，落地时再升下一档版本号，避免和这次配置版本重号。

## 1. 产品目标与规划假设

继续服务于家庭中的 8 岁孩子，以 iPad 为主要学习设备，英语先行。家长负责安排内容、陪伴和调整难度，孩子能够独立开始、继续和结束一次练习。

这轮迭代要达到三个结果：

1. 孩子打开 App 就知道今天做什么，任务量不会随复习积压无限增长。
2. 复习安排能够反映每个词的实际作答，家长能看到可执行的下一步建议。
3. 词表、进度、照片和家长录音可以完整备份并恢复。

规划沿用本机存储、无需账号的方式。数学、语文继续保留现状；本轮不扩展云同步、社交、排行榜、广告、AI 对话或自动发音评分。开发过程中不顺带重构无关页面。

“约 10 分钟”、新词数量、复习间隔和周报阈值都是待家庭试用验证的产品参数，不是针对所有儿童的学习标准。以实际完成情况调整，不承诺使用时长或学习效果。

版本号是计划槽位。若中途发布紧急修复，后续版本顺延并更新本文，不把两个独立发布复用同一个版本号。

这轮使用 patch 版本的前提是新版本能读取和保留旧数据、已有练习入口仍可使用。若实施方案必须破坏旧数据或已有使用方式，按仓库规则重新安排为 minor 版本，不能为保持路线表而强行使用 patch。

没有指定人力和截止日期，因此不填未经验证的日历排期。每个版本先满足发布条件，再进入下一版；学习规则变化至少观察一周家庭使用，文件备份以跨设备恢复实测为准。

## 4. 分阶段成果

### 阶段一：任务可控，数据可带走（0.1.26—0.1.27）

先限制 KET 单次日任务，并把“已经提交的题目”可靠保存。随后补齐完整备份，为后面的记录迁移提供恢复手段。

0.1.26 的上限只约束闯关；今日卡仍是独立练习。整个首页的统一日课和总完成状态在 0.1.29 交付，不能提前宣传为所有练习已合并。

### 阶段二：学过有依据，每天有主线（0.1.28—0.1.29）

复习以每词作答为依据，跟读自评与客观对错分别记录。建立按档案、日期、任务归属的本地事件，再让首页只组织一份当日计划。

完成计划奖励参与；正确率反映作答。两者分别展示，孩子出现错误仍可完成今天的任务。

### 阶段三：内容连贯，家长知道怎么调整（0.1.30—0.1.31）

用已有单元和家庭内容组成主题，不引入新内容平台。周报使用已收集的真实事件，给出少量有依据的建议。

## 5. 跨版本约定

### 5.1 数据与兼容

- 增加字段时给旧存档补默认值；保留词 ID、已有关卡星级、家长录音和书页引用。
- App 版本、存储 schema 版本、备份容器格式分别管理。App 升 patch 不等于修改 `PersistedState.version`。
- 每一版新增字段都要覆盖正常重启、旧备份导入、完整备份恢复三种入口。
- 不根据旧关卡星级推造逐题对错；无法归属的历史记录单列为历史数据，不计入孩子的新增指标。
- 不依靠打开页面、重复渲染或重复点按钮重复发奖、推进复习或生成事件。
- 同一天开始后的任务内容保持稳定，设置和主题变更次日生效；删除内容、跨日和升级例外由各版明确处理。
- 读取、解析或迁移失败应保留原始数据并显示恢复入口。不得因失败生成示例数据后自动覆盖原存档；这是 0.1.27 的发布条件。
- 新版能导入旧数据，不代表旧 App 能读取新版存档。回退使用升级前备份；禁止承诺直接降级可无损回退。

### 5.2 实施顺序

每个版本按以下顺序执行，任务完成前保持文档中的待办状态：

1. 确认版本基线，保存升级前备份，阅读该版本规格。
2. 用现有测试固定关键行为，为新增业务规则补必要的行为测试。
3. 实现纯逻辑和迁移，再接入持久化与页面。
4. 运行 `npm test`、`npm run typecheck`，修复该版本引入的问题。
5. 在 iPad 验证完整流程；涉及分享、照片和录音时同时验收实际文件。
6. 更新版本及说明，记录未解决限制，满足发布条件后标记完成。

前两版已执行自动化和构建检查；通过项目、依赖检查提示及未验收项记录在[验收记录](验收/0.1.26-0.1.27-验收记录.md)。

### 5.3 发布一致性

功能或修复发布时同步更新：

- `package.json` 与 `app.json` 的 `version`，这是仓库的强制要求。
- `src/constants/version.ts` 的界面版本。
- `README.md`、`AGENTS.md` 中当前版本说明；若锁文件含根包版本，检查其一致性。
- 对应规格的状态、验收结果以及本路线图。

本次前两版合并为开发版本 0.1.27，版本文件已同步；尚未完成真机发布验收。

### 5.4 真机共同验收

| 场景 | 通过标准 |
| --- | --- |
| iPad 横竖屏 | 主按钮、题目、答案反馈可见；切换方向不丢已提交结果 |
| iPhone 家长操作 | 设置、导入、备份确认可操作，无被键盘遮挡的关键按钮 |
| 离线学习 | 已有本地内容可练习，系统英语语音和家长录音按已有能力工作 |
| 返回/重启 | 已提交进度恢复，重复操作不重复发奖 |
| 日期变化 | 回到前台时确认新日期，旧题回调不会写入新一天 |
| 档案变化 | 不混入另一个孩子的内容；新引入的状态和事件明确归属 |
| 空内容/内容删除 | 有明确空态，不把“没有任务”写成“已经学会” |
| 旧数据升级 | 内容与已完成进度仍可用；新指标明确历史覆盖范围 |

不只用颜色表示对错；关键按钮提供可读名称；动态字号下检查换行。截图和浏览器检查不能替代真机的录音、系统分享与无障碍操作验收。

## 6. 观察指标

先记录当前家庭使用作为基线，避免给个人 App 设没有依据的增长目标。

| 要回答的问题 | 指标口径 | 采集方式/可用版本 |
| --- | --- | --- |
| 孩子能否独立完成？ | 启动日课中，无家长操作帮助且完成的次数 | 早期家长观察；不从点击事件推断“独立” |
| 一次练习是否太长？ | 实际练习耗时及中途退出原因 | 0.1.26 起人工计时；不把“约 10 分钟”直接当统计值 |
| 复习是否持续积压？ | 当天到期词、安排复习词、延期词 | 0.1.26 的计划计数；按日观察趋势 |
| 隔天是否还记得？ | 到期词的首次客观作答正确率，按题型区分 | 0.1.28 起；跟读自评不进入分母 |
| 主题是否省家长时间？ | 从选择单元到可开始日课的实际操作次数 | 0.1.30 家长试用记录 |
| 备份是否完整？ | 恢复后状态数量匹配，所有引用媒体可读取 | 0.1.27 起，在另一设备或独立干净实例实测 |

先追踪这些可观察结果，不追加使用时长排行、连续登录惩罚或推送系统。

## 7. 风险与处理

| 风险 | 处理 | 所属版本 |
| --- | --- | --- |
| 旧日任务已经很长，升级后直接截断会丢进度 | 当天保留原任务，提示新上限次日生效 | 0.1.26 |
| 复习一直多于上限，长期没有新词 | 显示延期数供家长判断；先观察，不暗中突破上限 | 0.1.26/0.1.31 |
| 打包媒体导致 iPad 内存或空间不足 | 先做文件能力与容量验证；分阶段写入，失败保留原数据 | 0.1.27 |
| 旧档案没有逐题结果和归属 | 保留历史，不补造准确率或归属 | 0.1.28/0.1.29 |
| 多入口重复记分，或者孩子切换后混算 | 使用档案/日期/任务标识去重，验收跨入口与跨档案 | 0.1.28/0.1.29 |
| 现有 400 条日志无法覆盖新周报 | 按日期保留并显式标记不完整区间 | 0.1.28 |
| 单元导入已有词被跳过，主题关联丢失 | 给已有词补关联，不复制词或覆盖家长修改 | 0.1.30 |
| 样本少却给出强结论 | 显示样本数，未达门槛时只展示记录 | 0.1.31 |

## 8. 依据、边界与后续细化

学习方向参考 [IES 的间隔学习和主动回忆建议](https://ies.ed.gov/ncee/wwc/PracticeGuide/1)。本文的具体数量、间隔和阈值是项目设计选择，并非该资料给出的儿童英语处方。

文件能力已通过 Context7 查询 Expo 官方资料：

- [DocumentPicker](https://docs.expo.dev/versions/latest/sdk/document-picker/)：选择文件后需要立即读取时，使用复制到缓存的方式。
- [Sharing](https://docs.expo.dev/versions/latest/sdk/sharing/)：iOS/Android 可分享本地文件 URI；Web 有不同限制。
- [FileSystem](https://docs.expo.dev/versions/latest/sdk/filesystem/)：文件读写和选择文件的组合方式。

文件方案已使用项目实际 SDK 57 依赖实现，ZIP 二进制往返、Web 和 iOS 打包均有本地验证。通用文档与本地打包不能替代 iPad 系统分享、真实媒体播放和容量验证；27-01 的真机部分仍待执行。

细化层次已经分开：本文件负责路线与共同约定；各版本规格负责规则、任务和验收；实施时在对应任务下补实际代码位置、测试结果与家庭观察，不另起一套冲突需求。
